## 1. 任务背景与目标

根据系统重构减负核心原则，GlossaHub **彻底废弃了繁琐复杂的五级 RBAC 角色权限与层层审批状态机**，采用企业内部高互信协作模式。  
但为了保证“不可变审计流水与时光机”的法律与合规严肃性，系统必须真实知晓“当前请求是谁发起的”：
1. **轻量登录 / 免登透传**：支持通过 JWT Token 或内部 SSO 请求头识别用户（姓名、工号、团队，如 `张工 (固件研发组)`）。
2. **上下文自动穿透**：通过 Node.js `AsyncLocalStorage`，自动将操作人注入到每一次变更审计日志的 `operator` 字段中，无需每个 Controller 手动传参。

---

## 2. 详细功能规格与实现要求

1. **Fastify 鉴权插件 (`jwt-auth.plugin.ts`)**：
   - 提取请求头 `Authorization: Bearer <token>` 或企业网关注入的 `X-Remote-User: <base64>`。
   - 开发与本地离线模式下，若未提供 Token，默认回退为 `local_dev (开发者免密)`。
2. **异步上下文穿透 (`operator-context.ts`)**：
   ```typescript
   export const operatorContextStorage = new AsyncLocalStorage<{ operator: string; userId: string }>();
   
   // 任何 Service 在写审计日志时：
   const currentOperator = operatorContextStorage.getStore()?.operator || 'System';
   ```

---

## 3. 验收标准 (Acceptance Criteria)

- [ ] 携带有效 Token 发起修改词条请求，生成的审计流水中 `operator` 字段精确对应 Token 中的用户姓名。
- [ ] 未登录且在受保护生产环境下发起写操作，返回标准 RFC 7807 `401 Unauthorized` 报文。
