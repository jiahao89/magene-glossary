## 1. 任务背景与目标

为彻底杜绝人为手工将词条导出再提交给固件代码仓库的低效断层，建设全自动化持续集成与持续交付体系：
1. **Pull Request 质量门禁 (Quality Gate)**：任何提交 PR 必须自动运行 TypeScript 静态检查与全量 5 大里程碑回归测试网（`npm test`），失败直接阻断合并。
2. **GitOps 固件代码自动编译推送 (Firmware Codegen)**：
   - 当固件研发组在代码仓库打上发布标签（如 `v2.0.0-rc1`）或 GlossaHub 管理员点击“封板发布”，自动触发 CI 运行 `npx glossa pull --format=c-header`。
   - 自动提交生成的 `strings_lang.h` 与 `strings_lang.c` 到固件仓库对应分支，并生成 PR / Commit，打通端到端工程闭环。

---

## 2. 详细功能规格与实现要求

### 2.1 CI 工作流步骤 (`.github/workflows/ci.yml`)
1. `actions/checkout@v4`
2. `actions/setup-node@v4` (Node.js 20)
3. `npm ci`
4. `npm run build:client` (验证前端打包无类型报错)
5. `npm test` (依次运行 M1 ~ M5 全量自动化测试)

### 2.2 固件编译工作流 (`.github/workflows/firmware-codegen.yml`)
- 触发方式：`workflow_dispatch` (手动指定版本) 或 `repository_dispatch` (GlossaHub 封板 Webhook)。
- 执行编译：运行 CLI 工具输出 C 语言头文件，验证无 Clang 编译器警告。
- 产出归档：打包为 Github Release Artifact 供固件工程师直接下载。
