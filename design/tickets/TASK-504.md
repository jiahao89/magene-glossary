## 1. 业务价值与用户故事 (User Story)
> **作为** 嵌入式固件工程师与质量负责人，  
> **我需要** 系统在译文落库前进行毫秒级静态规则质检（占位符一致性、硬件字长截断防爆框、成对标点符号、空译文），并在大模型初次输出违规时触发轻量自纠错（Self-Correction），  
> **以便于** 从源头 100% 杜绝因缺失 `%s`/`%d` 导致的嵌入式 C 语言 `printf` 固件崩溃死机（Hard Fault），并确保译文物理不超出码表小屏空间。

## 3. 技术契约与详细设计 (Technical Specification)

### 3.1 质检规则判定矩阵
| 规则类型 | 严重等级 | 检测逻辑 | 典型违规场景 |
| :--- | :---: | :--- | :--- |
| **占位符一致性** | `ERROR` (阻断落库) | 提取原文占位符（`%s`, `%d`, `%02d`, `{0}` 等），比对译文是否完全保留且类型匹配 | 原文包含 `%s`，译文丢失 `%s` 导致 C 源码空指针崩溃 |
| **屏幕物理字长** | `ERROR` (阻断落库) | 译文字符数与 `terms.max_chars` 比对，超过则报警 | 德语超长单词导致码表屏幕爆框截断 |
| **成对标点闭合** | `WARNING` | 检查引号 `""`、括号 `()` `[]` 是否闭合 | 翻译漏写半边后括号 |
| **空译文 / 乱码** | `ERROR` (阻断落库) | 文本为空、全空白或包含非法 Unicode 乱码控制符 | 模型吐空串或乱码 |

### 3.2 自纠错轻量微调契约
当首轮大模型翻译输出未通过质检时：
1. 立即构建包含错误原因惩罚项的纠错 Prompt：
   > *"警告：你上一轮生成的译文 '...' 超出了硬件屏幕限制（当前 22 字符，上限 18 字符）。请在保证原意的前提下，精简压缩为不超过 18 字符的表达！"*
2. 触发低 Temperature（0.1）的微调重试；
3. 二次纠错通过后正常落库，并附带纠错审计标记。

## 4. 验收条件清单 (Acceptance Criteria Checklist)
- [ ] 构造缺失 `%s` 或 `%d` 的恶意翻译，QA 引擎 100% 成功拦截，拒绝入库并返回明确校验报错；
- [ ] 构造字符数超出 `max_chars` 的译文，精准触发超长警告；
- [ ] 针对超长场景触发自纠错，模型在第二轮中自动精简缩短文案并最终通过质检；
- [ ] 静态规则检测性能极佳：单条词条规则执行耗时 $\le 2\text{ms}$。
