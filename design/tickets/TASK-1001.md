## 1. 任务背景与目标

目前前端界面已通过 `INITIAL_C606_TERMS` 等 mock 数据完整展示，后端 Fastify 领域微单体亦已实现全量核心路由（`/api/v2/terms`, `/api/v2/diff`, `/api/v2/audit`, `/api/v2/ai`）。  
本任务旨在打通前端与后端的 HTTP 通信链路：
1. 统一构建强类型的 API 请求层，严格对齐后端 DTO 结构。
2. 支持环境变量 `VITE_API_BASE_URL` 与 `VITE_USE_MOCK`，当后端未启动时优雅降级为本地 Mock 模式，当后端在线时无缝发起真实 RESTful 请求。

---

## 2. 详细功能规格与实现要求

### 2.1 API 客户端规范 (`client/src/api/client.ts`)
- 封装统一的 HTTP 拦截器，捕获 RFC 7807 统一错误响应（`application/problem+json`）。
- 统一携带 `X-Request-Id` 与当前操作人标识请求头。
- 提供网络重试机制（对幂等 GET 请求发生网络抖动时自动重试 1 次）。

### 2.2 接口模块覆盖
1. **词条模块 (`terms-api.ts`)**：
   - `GET /api/v2/terms` (支持分页、kw 模糊搜索、模块筛选、语言投影)
   - `PUT /api/v2/terms/:id/translation` (更新单语种译文)
   - `POST /api/v2/terms/:id/lock` (加锁/解锁)
   - `POST /api/v2/terms` (新增词条)
   - `DELETE /api/v2/terms/:id` (逻辑删除词条)
2. **差分与合并 (`diff-api.ts`)**：
   - `POST /api/v2/diff/compare` (版本双向比对计算)
   - `POST /api/v2/diff/apply` (选择性合并)
3. **审计与时光机 (`audit-api.ts`)**：
   - `GET /api/v2/audit/logs` (查询不可变变更流水)
   - `POST /api/v2/audit/rollback` (触发原子时光机回退并自动生成后悔药快照)

## 3. 验收标准 (Acceptance Criteria)

- [ ] 在 `VITE_USE_MOCK=false` 且后端正常运行时，多语言大网格首屏数据真实自 PostgreSQL 查询加载。
- [ ] 后端服务异常或断开时，前端弹出轻量级友好 Toast 提示，并允许切换至离线体验模式。
- [ ] 单元格保存时网络抓包可观察到标准的 `PUT /api/v2/terms/:id/translation` 请求及正确 Payload。
