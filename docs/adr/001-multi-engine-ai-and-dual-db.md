# ADR 001: 多引擎 AI 架构解耦与 PostgreSQL 妙搭部署双模支持

- **状态**: 已接受 (Accepted)
- **日期**: 2026-10-09
- **决策者**: GlossaHub 核心工程团队

---

## 背景 (Context)

原 `glossa-hub` 平台深度绑定单一 Dify 智能体工作流作为翻译后端。在实际工业级固件开发与批量协作中暴露出以下痛点：
1. **外部强依赖脆弱性**: 当 Dify 实例遭遇网络波动、网关 504 超时、403 鉴权失败或并发速率限制时，批量预翻译任务直接全部报红中断。
2. **云端部署受限**: 之前依赖 SQLite 或特定 Supabase 环境，无法直接 1-Click 部署在妙搭 (MiaoDa) 等标准化 PaaS 平台上。
3. **维护补丁泛滥**: 服务端散落大量针对特定 IP、特定错误文本的临时容错代码，代码可维护性差。

---

## 决策 (Decision)

1. **三模 AI 翻译矩阵**:
   - **大模型直连优先**: 支持 DeepSeek-V3、阿里通义千问等标准 OpenAI 兼容接口，降低延迟至 800ms 内。
   - **离线固件词库兜底**: 内置迈金高频固件术语库，在外部网络故障时 100% 自动无缝降级，确保批量任务零中断。
   - **兼容保留 Dify**: 作为可选智能体模式，保留与内部 Night 引擎的互通。
2. **PostgreSQL / SQLite 双引擎原生适配**:
   - 云端通过 `DATABASE_URL` 自动识别 PostgreSQL，开机执行幂等 DDL 及复合索引创建。
   - 提供独立初始化命令 `npm run db:init:pg` 供妙搭一键部署自检。
   - 本地开发保持零配置 SQLite (`glossahub.db`)。

---

## 影响与后果 (Consequences)

### 正向影响 (Positive)
- 彻底摆脱单一服务商断供或超时导致的系统不可用。
- 妙搭平台支持一键部署上线与自动扩缩容。
- 166 项自动化测试覆盖所有故障转移与降级分支。

### 负向影响与后续工作 (Negative & Mitigations)
- 需要维护两套 SQL 方言（后续将通过抽取 `Repository` 数据访问层彻底消除重复分支）。
